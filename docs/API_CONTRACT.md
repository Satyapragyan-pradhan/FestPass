# FestPass API Contract & Distributed Protocol Specification

This document defines the strict HTTP REST, Internal Peer-to-Peer, and Socket.IO contracts across all 6 stages of FestPass. Every node (B1..B3 booth nodes, G1..G3 gate nodes) implements these endpoints according to its role.

---

## 1. Global Conventions & Standards

### 1.1 Base URLs & Ports

- **Booth Nodes**:
  - `B1`: `http://localhost:4001`
  - `B2`: `http://localhost:4002`
  - `B3`: `http://localhost:4003`
- **Gate Nodes**:
  - `G1`: `http://localhost:4004`
  - `G2`: `http://localhost:4005`
  - `G3`: `http://localhost:4006`

### 1.2 Common HTTP Headers

- `Content-Type: application/json`
- `X-Request-Id`: Unique UUID generated by client or gateway; propagated in all logs and response headers.
- `Authorization: Bearer <jwt_token>` (for authenticated endpoints)

### 1.3 Standard Success Response Envelope

```json
{
  "success": true,
  "data": { ... }
}
```

### 1.4 Standard Error Response Envelope

```json
{
  "success": false,
  "error": {
    "code": "BAD_REQUEST | UNAUTHORIZED | FORBIDDEN | NOT_FOUND | CONFLICT | OVER_QUOTA | INVALID_TOKEN | ALREADY_USED | REPLICATION_ERROR | PEER_UNREACHABLE | INTERNAL_ERROR",
    "message": "Human-readable description of error",
    "details": [ ... ]
  }
}
```

## 2. Health & Node Diagnostics Endpoints

### 2.1 Health Probe

- **Method & Path**: `GET /health`
- **Auth / Role**: Public
- **Description**: Lightweight health probe for load balancers and process monitors.
- **Response `200 OK`**:

```json
{
  "status": "ok",
  "nodeId": "B1",
  "timestamp": "2026-10-30T10:15:00.000Z",
  "uptime": 124
}
```

### 2.2 Node Diagnostics & Metadata

- **Method & Path**: `GET /node/info`
- **Auth / Role**: Public
- **Description**: Returns local node role, current HLC logical time, uptime, and peer topology tracking.
- **Response `200 OK`**:

```json
{
  "nodeId": "B1",
  "role": "booth",
  "nodeIndex": 1,
  "hlc": "1761819300000:0:B1",
  "uptime": 124,
  "peersConfigured": 6,
  "peersTracked": 6
}
```

  "password": "Password123!"

## 5. Ticket Sales & Lookup (Implemented in Stage 2)

### 5.1 Issue / Sell Ticket (Booth Node Only)

- **Method & Path**: `POST /api/tickets/issue`
- **Auth / Role**: `booth_staff` or `admin`
- **Node Role Requirement**: Node must have `NODE_ROLE=booth` (or `both`) and hold Ed25519 private key.
- **Request Body**:

```json
{
  "eventId": "173829103810293855",
  "holderName": "Sarah Jenkins",
  "holderEmail": "sarah.j@campus.edu",
  "holderPhone": "+15550192834"
}
```

- **Response `201 Created`**:

```json
{
  "success": true,
  "ticket": {
    "ticketId": "173829103810293899",
    "eventId": "173829103810293855",
    "holderName": "Sarah Jenkins",
    "holderEmail": "sarah.j@campus.edu",
    "holderPhone": "+15550192834",
    "status": "valid",
    "token": "FP1.173829103810293899.173829103810293855.9aF8c1D4...",
    "issuedAtHlc": "1761819305120:0:B1"
  }
}
```

- **Error Codes**:
  - `400 BAD_REQUEST`: Invalid input formatting
  - `403 FORBIDDEN`: Node is not a booth node
  - `409 OVER_QUOTA`: Booth node has exhausted its allocated quota partition

### 5.2 Get Ticket by ID

- **Method & Path**: `GET /api/tickets/:id`
- **Auth / Role**: Authenticated / Public
- **Response `200 OK`**: Returns ticket object.
- **Error Codes**: `404 NOT_FOUND`.

### 5.3 Query Tickets by Email, Phone, or Event

- **Method & Path**: `GET /api/tickets?email=...&phone=...&eventId=...`
- **Auth / Role**: `booth_staff`, `gate_staff`, `admin`
- **Response `200 OK`**:

```json
{
  "success": true,
  "tickets": [ ... ]
}
```

### 5.4 Revoke Ticket

- **Method & Path**: `POST /api/tickets/:id/revoke`
- **Auth / Role**: `admin`
- **Request Body**:

```json
{
  "reason": "Customer requested refund"
}
```

- **Response `200 OK`**:

```json
{
  "success": true,
  "ticket": {
    "ticketId": "173829103810293899",
    "status": "revoked",
    "reason": "Customer requested refund"
  }
}
```

## 6. Gate Scanning & Validation (Implemented in Stage 4)

### 6.1 Online / Offline Ticket Validation

- **Method & Path**: `POST /api/gate/scan`
- **Auth / Role**: `gate_staff` or `admin`
- **Description**: Validates the cryptographic Ed25519 signature. If online, queries peer gates to achieve distributed consensus; if offline, validates signature locally and queues for anti-entropy sync.
- **Request Body**:

```json
{
  "token": "FP1.173829103810293899.173829103810293855.9aF8c1D4...",
  "mode": "online",
  "offlineHlc": null
}
```

- **Response `200 OK` (Accepted)**:

```json
{
  "success": true,
  "checkinId": "173829103810293910",
  "ticketId": "173829103810293899",
  "eventId": "173829103810293855",
  "result": "accepted",
  "mode": "online",
  "hlc": "1761819310000:0:G1"
}
```

- **Response `200 OK` (Rejected Duplicate)**:

```json
{
  "success": false,
  "result": "rejected_duplicate",
  "ticketId": "173829103810293899",
  "firstCheckedInAt": "2026-10-30T10:15:30.000Z",
  "gateNodeId": "G2"
}
```

- **Response `200 OK` (Rejected Invalid)**:

```json
{
  "success": false,
  "result": "rejected_invalid",
  "error": "Signature verification failed: token is forged or tampered"
}
```

### 6.2 Offline Batch Checkin Replay

- **Method & Path**: `POST /api/gate/scan-offline-batch`
- **Auth / Role**: `gate_staff` or `admin`
- **Description**: Submits an array of scans accumulated during network disconnection. Replays events ordered by HLC and identifies concurrent double-scan conflicts.
- **Request Body**:

```json
{
  "scans": [
    {
      "token": "FP1.173829103810293899.173829103810293855.9aF8c1D4...",
      "gateNodeId": "G1",
      "hlc": "1761819308100:0:G1",
      "scannedAt": "2026-10-30T10:15:08.100Z"
    }
  ]
}
```

- **Response `200 OK`**:

```json
{
  "success": true,
  "processed": 1,
  "accepted": 1,
  "conflicts": []
}
```

### 6.3 Gate Checkin History

- **Method & Path**: `GET /api/gate/checkins?limit=50`
- **Auth / Role**: `gate_staff`, `admin`
- **Response `200 OK`**:

```json
{
  "success": true,
  "checkins": [ ... ]
}
```

## 8. Internal Peer-to-Peer Protocol Endpoints (Stages 3 & 4)

These endpoints are internal to node processes and execute inter-node distributed algorithms.

### 8.1 Peer Gossip Protocol

- **Method & Path**: `POST /internal/gossip`
- **Description**: Heartbeat and membership state exchange. Also synchronizes local HLC against sender's clock.
- **Request Body**:

```json
{
  "originNodeId": "B2",
  "hlc": "1761819325000:0:B2",
  "peers": [
    { "nodeId": "B1", "url": "http://localhost:4001", "role": "booth", "lastSeen": 1761819324000 },
    { "nodeId": "B2", "url": "http://localhost:4002", "role": "booth", "lastSeen": 1761819325000 }
  ]
}
```

- **Response `200 OK`**: `{ "success": true }`

### 8.2 Anti-Entropy State Machine Replication Sync

- **Method & Path**: `POST /internal/sync`
- **Description**: Pull-based catch-up protocol. Returns operations in `op_log` strictly after `fromHlc`.
- **Request Body**:

```json
{
  "originNodeId": "G3",
  "fromHlc": "1761819310000:0:G3",
  "limit": 100
}
```

- **Response `200 OK`**:

```json
{
  "success": true,
  "currentHlc": "1761819330000:0:B1",
  "ops": [
    {
      "op_id": "173829103810293990",
      "origin_node": "B1",
      "hlc": "1761819315000:0:B1",
      "type": "TICKET_ISSUED",
      "payload_json": "{\"ticketId\":\"...\"}"
    }
  ],
  "remaining": 0
}
```

### 8.3 Distributed Quota Rebalancing Claim

- **Method & Path**: `POST /internal/claim`
- **Description**: Allows a booth node running low on quota to request a slice of quota from a peer booth node.
- **Request Body**:

```json
{
  "eventId": "173829103810293855",
  "targetNodeId": "B1",
  "amount": 50
}
```

- **Response `200 OK`**:

```json
{
  "approved": true,
  "transferred": 50,
  "newQuota": 150
}
```

### 8.4 Chaos & Simulation Hook (Stage 6)

- **Method & Path**: `POST /internal/chaos`
- **Description**: Simulates network delay, packet drop, or partition between nodes.
- **Request Body**:

```json
{
  "action": "delay | partition | drop | reset",
  "targetNodeId": "G2",
  "delayMs": 500,
  "enabled": true
}
```

- **Response `200 OK`**:

```json
{
  "success": true,
  "message": "Chaos configuration accepted (Stage 6 hook)"
}
```

## 9. Socket.IO Real-Time Events

The server initializes Socket.IO at the root path (`/socket.io/`). Clients and dashboards connect to receive real-time cluster telemetry.

### 9.1 `cluster:update`

- **Direction**: Server -> Client
- **Payload**:

```json
{
  "nodeId": "B1",
  "hlc": "1761819340000:0:B1",
  "activePeers": 6,
  "status": "healthy"
}
```

### 9.2 `ticket:issued`

- **Direction**: Server -> Client
- **Payload**:

```json
{
  "ticketId": "173829103810293899",
  "eventId": "173829103810293855",
  "issuedByNode": "B1",
  "holderName": "Sarah Jenkins",
  "issuedAtHlc": "1761819305120:0:B1"
}
```

### 9.3 `checkin:result`

- **Direction**: Server -> Client
- **Payload**:

```json
{
  "checkinId": "173829103810293910",
  "ticketId": "173829103810293899",
  "gateNodeId": "G1",
  "result": "accepted",
  "mode": "online",
  "hlc": "1761819310000:0:G1"

```

### 9.4 `conflict:detected`

- **Direction**: Server -> Client
- **Payload**:

```json
{
  "ticketId": "173829103810293899",

```
